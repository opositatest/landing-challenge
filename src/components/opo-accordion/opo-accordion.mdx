# Accordion

## Overview

`opo-accordion` is a composable disclosure component used to progressively reveal related content sections.

The component is built with `Stencil` and `Shadow DOM`, offering:

- single and multiple expansion modes,
- controlled and uncontrolled state,
- responsive spacing,
- semantic heading levels,
- accessible keyboard interaction,
- smooth panel expansion transitions,
- and visual variants for constrained or outlined layouts.

The accordion is composed of two elements:

- `opo-accordion` → parent container and state manager
- `opo-accordion-item` → individual expandable item

---

## Import

```ts
import "@opo/components/opo-accordion";
import "@opo/components/opo-accordion-item";
```

---

## Usage

```html
<opo-accordion type="multiple" default-value="faq-1 faq-2">
  <opo-accordion-item value="faq-1" label="¿Los test de oposiciones de OpositaTest son gratuitos?">
    <p>Sí. Puedes acceder a una selección de test gratuitos para empezar a practicar.</p>
  </opo-accordion-item>

  <opo-accordion-item value="faq-2" label="¿Cómo estudiar para oposiciones tipo test?">
    <p>Lo ideal es combinar teoría, simulacros y revisión de errores.</p>
  </opo-accordion-item>
</opo-accordion>
```

---

## Variants

### Default

Provides the default elevated accordion appearance using the system shadow token.

```html
<opo-accordion variant="default">
  <!-- items -->
</opo-accordion>
```

### Outlined

Displays the accordion using a bordered container style.

```html
<opo-accordion variant="outlined">
  <!-- items -->
</opo-accordion>
```

---

## Selection modes

### Multiple

Allows several accordion items to remain open simultaneously.

```html
<opo-accordion type="multiple">
  <!-- items -->
</opo-accordion>
```

### Single

Only one item can remain open at a time.

```html
<opo-accordion type="single">
  <!-- items -->
</opo-accordion>
```

---

## Controlled vs uncontrolled

### Uncontrolled

The accordion manages its internal state using `default-value`.

```html
<opo-accordion type="multiple" default-value="faq-1 faq-2">
  <!-- items -->
</opo-accordion>
```

### Controlled

The open state is controlled externally using `value`.

```html
<opo-accordion type="single" value="faq-2">
  <!-- items -->
</opo-accordion>
```

The component emits `opoChange` whenever the requested open state changes.

---

## Full width

Use `full-width` to allow the accordion to expand across the available container width.

```html
<opo-accordion full-width>
  <!-- items -->
</opo-accordion>
```

---

## Semantic heading levels

Accordion items support semantic heading levels independently from their visual appearance.

```html
<opo-accordion-item value="faq-1" label="Question" heading-level="4"> Content </opo-accordion-item>
```

The visual style remains consistent regardless of the selected heading level.

---

## Accessibility

The accordion follows the disclosure pattern using:

- semantic `button` controls,
- `aria-expanded`,
- `aria-controls`,
- `role="region"`,
- keyboard interaction support,
- and focus-visible styling.

Each accordion item:

- toggles with `Enter` and `Space`,
- exposes semantic heading structure,
- and keeps state synchronized through ARIA attributes.

Decorative icons are marked with `aria-hidden="true"`.

---

## Responsive behavior

The component uses a mobile-first responsive strategy.

Spacing and indentation adapt automatically at the `--ref-breakpoint-md` breakpoint.

Long labels support multiline wrapping while preserving icon alignment and trigger spacing.

---

## Motion

The accordion panel uses a CSS Grid expansion pattern:

```css
grid-template-rows: minmax(0, 0fr);
grid-template-rows: minmax(0, 1fr);
```

This approach allows smooth height transitions while preserving overflow clipping and responsive content behavior.

The chevron icon rotates during expansion and respects `prefers-reduced-motion`.

## Do / Don’t

### ✅ Do

- Use semantic heading levels according to the page hierarchy.
- Use `single` mode when only one section should remain visible.
- Use `multiple` mode for FAQ-style content.
- Keep trigger labels concise and descriptive.
- Allow labels to wrap naturally on smaller screens.
- Use `full-width` inside fluid layouts.

### ❌ Don’t

- Don’t place interactive controls inside the trigger label.
- Don’t use overly long labels without considering responsive wrapping.
- Don’t rely exclusively on visual state changes to communicate expansion.
- Don’t remove focus-visible styles.
- Don’t use the accordion for unrelated or disconnected content sections.
