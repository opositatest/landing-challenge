# opo-button

Botón de acción reutilizable del **Design System OPO**.

El componente está construido con `Stencil` y `Shadow DOM`, ofreciendo:

- variantes visuales,
- tamaños,
- estados interactivos,
- accesibilidad básica,
- soporte para iconos mediante slots,
- y loaders customizables.

---

## Import

```tsx
import "@opo/components/opo-button";
```

---

## Basic usage

```html
<opo-button>Guardar</opo-button>
```

---

## Variants

El componente soporta distintas variantes visuales:

- `primary`
- `secondary`
- `ghost`
- `destructive`

### Primary

```html
<opo-button variant="primary">Guardar</opo-button>
```

### Secondary

```html
<opo-button variant="secondary">Cancelar</opo-button>
```

### Ghost

```html
<opo-button variant="ghost">Más información</opo-button>
```

### Destructive

```html
<opo-button variant="destructive">Eliminar</opo-button>
```

---

## Sizes

El tamaño visual se controla mediante la prop `size`.

```html
<opo-button size="sm">Small</opo-button>
<opo-button size="md">Medium</opo-button>
<opo-button size="lg">Large</opo-button>
```

---

## Icon buttons

El componente soporta botones solo-icono mediante la prop `iconOnly`.

En este modo:

- el label visual no se renderiza,
- el botón mantiene accesibilidad mediante `ariaLabel`,
- y el tamaño visual sigue controlándose mediante `size`.

```html
<opo-button variant="ghost" size="md" icon-only aria-label="Buscar">
  <opo-icon slot="icon-start" name="search"></opo-icon>
</opo-button>
```

> [!IMPORTANT]
> Los botones solo-icono deberían proporcionar siempre `ariaLabel` para mantener un nombre accesible.

> [!NOTE]
> En HTML se usa como atributo kebab-case (`icon-only`), mientras que en JSX/TSX se consume como prop camelCase (`iconOnly`).

## Icons

Los iconos se insertan mediante slots:

- `icon-start`
- `icon-end`

### Start icon

```html
<opo-button>
  <opo-icon slot="icon-start" name="search"></opo-icon>
  Buscar
</opo-button>
```

### End icon

```html
<opo-button>
  Continuar
  <opo-icon slot="icon-end" name="arrow-right"></opo-icon>
</opo-button>
```

### Both icons

```html
<opo-button>
  <opo-icon slot="icon-start" name="search"></opo-icon>
  Buscar
  <opo-icon slot="icon-end" name="arrow-right"></opo-icon>
</opo-button>
```

---

## Loading state

La prop `loading`:

- muestra un loader,
- bloquea la interacción,
- y aplica `aria-busy` automáticamente.

```html
<opo-button loading>Procesando</opo-button>
```

### Custom loader

El slot `loader` permite sustituir el loader interno por cualquier contenido compatible.

```html
<opo-button loading>
  Guardar
  <opo-icon slot="loader" name="refresh-cw" size="sm" spinning></opo-icon>
</opo-button>
```

---

## Disabled state

```html
<opo-button disabled>Deshabilitado</opo-button>
```

---

## Full width

La prop `fullWidth` hace que el botón ocupe todo el ancho disponible del contenedor.

```html
<opo-button full-width>Continuar</opo-button>
```

---

## Accessibility

El componente incorpora:

- botón nativo HTML,
- soporte de teclado nativo,
- soporte para `aria-label`,
- `aria-busy` automático durante loading,
- y focus management mediante `:focus-visible`.

Los botones solo-icono deberían proporcionar siempre un nombre accesible:

```html
<opo-button icon-only aria-label="Buscar">
  <opo-icon slot="icon-start" name="search"></opo-icon>
</opo-button>
```

## Do / Don’t

### Do

- Usa `iconOnly` únicamente cuando el botón represente una acción claramente reconocible.
  Los botones solo-icono eliminan el texto visible, por lo que deberían reservarse para acciones comunes y fácilmente identificables.

- Proporciona siempre `ariaLabel` en botones solo-icono.
  El icono visual no genera automáticamente un nombre accesible; sin una etiqueta, el botón puede ser incomprensible para lectores de pantalla.

- Usa `destructive` solo para acciones destructivas, irreversibles o potencialmente peligrosas.
  Esto mantiene la jerarquía visual del sistema y evita que el estilo destructivo pierda significado.

### Don’t

- No uses botones para navegación entre páginas o vistas.
  Para navegación utiliza `opo-link`, porque mantiene semántica nativa de enlace y comportamiento esperado del navegador.

- No dependas únicamente del color para transmitir significado.
  Los estados críticos deberían apoyarse también en texto, contexto o estructura accesible.

- No coloques múltiples botones primarios juntos sin una jerarquía clara.
  La interfaz debería guiar hacia una acción principal y usar variantes secundarias para acciones de apoyo.

---

## Notes

- `opo-button` usa un `<button>` nativo dentro de Shadow DOM.
- Los estilos internos están desacoplados mediante Design Tokens.
- Las transiciones utilizan motion tokens compartidos del sistema.
- Los icon buttons utilizan un pequeño optical alignment para mejorar el centrado visual de iconos.
- Usa `opo-link` cuando la intención principal sea navegar.
